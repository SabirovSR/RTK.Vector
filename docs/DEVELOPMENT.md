# Разработка РТК Вектор

Рабочий MVP CRM на FastAPI, React и PostgreSQL. В репозитории сохранены исходная концепция и материалы кейса. Реализация расположена в `backend` и `frontend`.

## Запуск

Нужен запущенный Docker Desktop с Linux containers. Команды выполняются из корня репозитория:

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose exec backend python -m app.cli seed
docker compose exec backend python -m app.cli import-vendors --file /data/Вендоры.xlsx
```

`seed` и импорт вендоров допускают повторное выполнение без дублирования записей. Приложение не загружает исходные персональные данные автоматически.

- Приложение: http://localhost:5173
- Почта Mailpit: http://localhost:8025
- Swagger: http://localhost:5173/api/v1/docs
- Контракт API: http://localhost:5173/api/v1/openapi.json
- Проверка готовности: http://localhost:5173/api/v1/health

Используйте `localhost`, соответствующий `FRONTEND_URL`: запросы с другим Origin отклоняются. Для другого адреса измените `FRONTEND_URL` и пересоздайте сервисы. Порты приложения и Mailpit привязаны только к loopback.

Демонстрационные учётные записи, пароль по умолчанию `VectorDemo2026!`:

- `school@demo.test` — менеджер ИТ-школы, основной портфель.
- `colleague@demo.test` — второй менеджер ИТ-школы, отдельный портфель.
- `university@demo.test` — первый университет.
- `other@demo.test` — второй университет для проверки изоляции.

Пароль задаётся переменной `DEMO_PASSWORD` до первого выполнения seed. Данные вузов, сделок, групп и участников в демонаборе синтетические. Справочник вендоров загружается отдельно из предоставленного XLSX.

Данные сохраняются в томах PostgreSQL и документов. `docker compose down` останавливает сервисы и сохраняет тома. Не добавляйте `-v`, если данные нужны.

Создание менеджера без интерфейса администратора:

```powershell
docker compose exec backend python -m app.cli create-manager --email manager@organization.ru --name "Имя Фамилия"
```

Команда интерактивно запрашивает пароль. Представителей вузов приглашайте из карточки закреплённого вуза. Письмо с одноразовой ссылкой появится в Mailpit. Приглашение действует 72 часа, восстановление пароля — 1 час.

## Сквозной сценарий

1. Войти менеджером ИТ-школы, добавить вуз, контакт и пригласить представителя.
2. Создать сотрудничество, заполнить квалификацию: ответственный, интерес, бюджет, учебное окно.
3. Перевести в квалификацию и согласование, опубликовать предложение программы.
4. Представитель принимает приглашение и входит через второй вариант входа. На вкладке программы он согласует предложение либо отправляет замечания.
5. При замечаниях менеджер публикует новую версию. Решение по старой версии не даёт согласования новой.
6. Перейти к договору и подготовке. Загрузить подписанный PDF/DOCX/XLSX, отметить подготовку либо объяснить неприменимость каждого пункта.
7. Создать группу. Представитель вуза добавляет студентов и преподавателей вручную или через импорт, проверяет предпросмотр и подтверждает список.
8. Менеджер запускает обучение. После этого состав группы неизменно заблокирован, в том числе после возврата сделки назад.
9. На вкладке групп запустить демонстрационную синхронизацию. Worker записывает результаты: прогресс 100%, посещаемость 92%, оценка 85. Повтор не создаёт дубликаты.
10. Вуз видит индивидуальные результаты и скачивает PDF-сертификат с маркировкой DEMO. ИТ-школа видит только агрегаты.
11. Менеджер переводит сотрудничество в оценку результатов и завершает. Вуз оставляет отзыв и запрашивает новую программу/группу. Менеджер создаёт связанное продолжение.

Переходы строго последовательны; возврат и отказ требуют причины. Новая версия предложения после договора требует возврата на этап согласования. Успешное завершение невозможно, пока у каждого студента нет результата и прогресса 100%.

## Исходные файлы и импорт

Импорт участников доступен только менеджеру соответствующего вуза в конкретной группе до запуска обучения. XLSX читает первый лист и поля Фамилия, Имя, Отчество (включая исходное название `Отчествопри наличии)`), Email и Номер телефона. Остальные столбцы, включая СНИЛС и паспорт, показываются как пропущенные и не сохраняются.

Предпросмотр ничего не записывает. Ошибка в любой строке блокирует весь импорт. Email нормализуется к нижнему регистру, телефон — к цифрам с ведущим `+` и заменой российского префикса 8 на 7. Неоднозначный дубль требует исправления исходного файла. Повтор полностью совпадающей записи не создаёт нового участника. Изменение состава сбрасывает подтверждение группы.

JSON `Данные оплат.json` — заявки, а не бухгалтерские платежи. Начальный `null` пропускается. Номер заявки — уникальный внешний идентификатор. Курс сохраняется как исходное название, вуз и группа берутся из явно выбранного контекста. Номер потока в файле не используется для автоматического назначения группы. Финансовые суммы, факт оплаты и даты платежей не вычисляются.

Импорт ограничен 20 МБ, 5000 записями и 100 МБ распакованного XLSX. Повтор номера заявки с другими данными возвращает конфликт. Состав группы после начала обучения не меняется.

## API и архитектура

- `backend/app/models.py` — сущности SQLAlchemy; начальная миграция содержит фиксированный снимок схемы.
- `domain.py` — принадлежность записей, представления данных и условия переходов.
- `main.py` — REST-команды, сессии, загрузка и скачивание файлов.
- `imports.py` — разбор, предпросмотр, нормализация и запись импортов.
- `worker.py` — очередь PostgreSQL с блокировкой `SKIP LOCKED`; почта и демонстрационная LMS. Ошибка не теряется, повтор доступен автору операции в разделе интеграций.
- `frontend/src` — интерфейс React, маршруты, TanStack Query и компоненты shadcn/ui на Radix (адаптированы к локальному CSS). Шрифты упакованы вместе с приложением, внешних CDN нет.

Сессия живёт 12 часов. Cookie HttpOnly / SameSite=Lax, изменяющие запросы требуют CSRF-токен и допустимый Origin. Для HTTPS предусмотрен `COOKIE_SECURE=true`. Пароли хешируются Argon2id. Токены приглашений, восстановления и сессий в основной таблице хранятся хешированными. Очередь доставки содержит исходную ссылку до отправки письма, затем содержимое удаляется. Токены из query string исключены из access-log nginx.

Каждая операция чтения/изменения проверяет роль и принадлежность записи. У вуза нет внутренних заметок и квалификации в API; школа не получает списки студентов, результаты отдельных участников и сертификаты. Аудит содержит тип действия и идентификатор сущности, без копирования персональных данных.

Документы сохраняются под случайными именами вне web-root, проверяется тип контейнера и размер. Скачивание всегда проходит проверку доступа. Обмен подписанными файлами не проверяет юридическую действительность подписи и не является ЭДО.

Сайт отправляет `POST /api/v1/integrations/website/applications` с `X-Service-Key`. Тело: `external_id`, `group_id`, `course`, `participant` с ФИО (`name`), email, телефоном и типом участника. Сервисный ключ предназначен только для доверенного серверного интегратора, не для браузера сайта.

Демонстрационный отправитель (выберите существующую группу до начала обучения):

```powershell
python scripts/website-demo.py --group 1 --external-id WEBSITE-DEMO-001
```

Синхронизация LMS детерминирована и отмечена как демонстрационная. Реальные API LMS/SSO/телефонии/мессенджеров и электронная подпись не подключены. Worker отправляет только локальную почту Mailpit, пока не изменён SMTP_HOST.

## Локальная разработка

Для быстрого backend-теста допустима SQLite; основной путь запуска и интеграционные тесты используют PostgreSQL.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
cd backend
..\.venv\Scripts\python -m alembic upgrade head
..\.venv\Scripts\python -m app.cli seed
..\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В отдельном терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на localhost:8000. Для фоновых операций нужен отдельный `python -m app.worker` и SMTP-сервис. Не запускайте Vite на 5173 одновременно с Docker frontend на том же порту.

Обновление контракта и типов:

```powershell
cd backend
..\.venv\Scripts\python -m app.export_openapi
cd ../frontend
npm run api:types
npm run build
```

## Проверки

Быстрые API-тесты используют изолированную временную SQLite и синтетические записи:

```powershell
cd backend
..\.venv\Scripts\python -m pytest -q
```

Для PostgreSQL создайте отдельную тестовую базу. **Тесты пересоздают все таблицы в TEST_DATABASE_URL; никогда не указывайте рабочую базу.** Пример для настроек `.env.example`:

```powershell
docker compose exec db psql -U vector -c "CREATE DATABASE vector_test"
docker compose exec -e TEST_DATABASE_URL=postgresql+psycopg://vector:vector-local-dev@db:5432/vector_test backend python -m pytest -q
```

E2E выполняются на запущенном Docker-приложении с демоданными и Mailpit. Тест полного цикла создаёт отдельный тестовый вуз и собственные записи, не меняет исходные данные пользователя.

```powershell
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

Сценарии покрывают вход, приглашение по реальному письму Mailpit, согласование с новой версией, договор, подготовку и подтверждение группы, обучение, сертификат, отзыв и продолжение. Дополнительно проверяются кабинеты на 1440/768 px и отсутствие ошибок JavaScript.

Код не подтверждает юридического соответствия 152-ФЗ и требованиям ФСТЭК. До работы с реальными данными нужны отдельные мероприятия по инфраструктуре, резервированию, регламентам доступа и защите персональных данных.
